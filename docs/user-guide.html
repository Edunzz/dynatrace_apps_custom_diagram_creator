User guide

Everything you can do on the diagram list and in the editor.

The diagram list

The start page lists every diagram with its owner and dates. Click anywhere on a row to open it. The row actions duplicate, download (JSON) or delete a diagram; select several rows to download or delete them together.

  • New diagram opens an empty canvas in edit mode.
  • Upload imports one or more .json files. They are validated against the schema; if a diagram with the same id exists, the upload gets a new id.
  • ⓘ About shows the version, the author and links to the source code and these docs.
  • ⚙ Storage administration lists the app's lookup files and can delete one.

Adding components

In edit mode, drag a component from the palette onto the canvas (or click it to drop it in the middle). Its editor opens docked on the right.

Entity components — mobile, frontend, service, process, host and workload — run a DQL query that returns one or more entities. Each type starts from a Smartscape template you can edit:

dql
smartscapeNodes "SERVICE"
| filter contains(name, "<text>", caseSensitive: false)
| fields id, name

The query must return an id column (and preferably name). Use Run to preview the result: Run also applies the query to the diagram and refreshes the component.

On the Status tab you set when the component changes color:

  • Warning threshold — number of active problems to turn orange.
  • Failing threshold — number of active problems to turn red (red wins when both are equal).
  • Match — an optional DQL fragment appended as | filter … to the problem query, e.g. event.category == "ERROR".

Custom components (containers)

A custom component is a large container with one row per child, each with its own status light.

  • Entities mode — a DQL query that returns id and name. Choose which column names each child and whether any active problem turns a child red, or only the problems that match a filter.
  • SLOs mode — pick SLOs; each row shows the current value and error budget. SLOs are evaluated with the timeframe defined in each SLO.

The container itself is red when every child is red, orange when some child is red or orange, and green when all are green. A container with a single entity shows it as one big block.

KPI blocks

Any node can show a compact table under it. On the KPIs tab, turn on Show KPIs under the node and write a query that returns a table:

dql
timeseries rt = avg(dt.service.request.response_time, scalar: true), by: {dt.smartscape.service}
| fieldsAdd service = getNodeName(dt.smartscape.service), avg_ms = rt / 1000
| fields service, avg_ms
| sort avg_ms desc
| limit 5

Connections

Drag from the dots on the side of a node to another node. The connection editor opens so you can choose:

  • Normal — a plain line with an optional label.
  • KPI relation — a query that returns a single value (first row; the chosen column or the first numeric one), a unit, decimals and a threshold. above means high values are bad, below means low values are bad.

Every connection has a direction — source to target, target to source, or no arrow. KPI connections show a pill with the value, color the line by status and animate dots in the arrow's direction (off when the system asks for reduced motion).

dql
timeseries r = avg(dt.service.request.response_time, scalar: true)
| fieldsAdd v = r / 1000
| fields v

Editing like a dashboard

  • Select a node to get the floating toolbar: its size, Duplicate, Edit and a ⋮ menu with View details and Delete. Selected connections get Edit and Delete.
  • Resize any node from the grips in its bottom corners.
  • Edit in the panel docked to the right. There is no Apply button: names, icons and labels change on the canvas as you type, Run applies a query, and threshold or filter changes refresh the status after a short pause.
  • While the editor is open, click another element to switch to it.
  • Each editing session is one undo step.

View mode and details

In view mode, click a node or a KPI connection to open its details on the right:

  • the applied timeframe, in your time zone;
  • the entity query and the full problem query, with the timeframe and ids already filled in — copy them or open them in Notebooks;
  • the problems in the timeframe, each linking to the Problems app;
  • the breakdown per child or per SLO, and for KPI connections the raw value and how the threshold was evaluated.

Saving, sharing and versions

Save writes the diagram to the lookup table. If someone else saved it after you opened it, the app asks whether to Overwrite their version or Reload theirs. Export JSON downloads a file you can upload again without losing anything — use it to move diagrams between environments or to keep them in Git.
